# U3 review: `feature/phase0-u3-servo-core` (01fab9c) vs `main`

This was an adversarial grill review on 2026-10-01: 3 attackers, then 3 defenders challenging their findings. **Verdict: REQUEST_CHANGES**, with 4 blocking findings and 12 should-fix.

**User decisions, 2026-10-02** (also logged in plan §10):

- Item 5: latch only after 5 consecutive misses.
- Item 9: add a `read_ok` flag to the state record.
- Scope: fix every blocking and should-fix item. Nits are optional.

**What the review found already holds:**

- `validate_geometry` runs inside `build_servo_core`.
- A heartbeat is sent before every reenergize, and only after a good read and an accepted write.
- TORQUE_OFF keeps writing goal = present and keeps heartbeating.
- No `McuStatus` is fed into the state machine before ARM.
- Signal handlers only set a flag, and shutdown is idempotent.
- A stale shm segment is replaced with zeroed memory.
- `bound_s` is 20 s.

## BLOCKING

1. **`core.py:311` + `feetech_bus.py:72`: `bus.connect()` runs a ping handshake before ARM.**
   The MCU boots LATCHED with the relay open, and ARM requires the servo side to be unpowered. So on the real arm the handshake raises `ConnectionError`, and the process exits with `EXIT_STARTUP` every time. The tests miss this because the fake `connect` never pings.
   **Fix:**
   - Open the port with `handshake=False` before ARM.
   - Ping the motors after ARM and before reenergize.
   - Add a FakeBus "unpowered until ARM" mode, with a test.
2. **`core.py:594-595`: `_send_heartbeat` advances `_hb_seq` before it knows the send worked.**
   When a write times out, the frame never reaches the MCU, which leaves a gap in the sequence. On the lenient paths (the shutdown hook `:713` and the boot retry window `:316-329`), the next heartbeat then latches SEQ_ERROR and opens the relay mid-ramp, so the arm drops. Reproduced with FakeMcu: `fail_writes(1)` during shutdown latches with reason 3.
   **Fix:** make `HeartbeatLink.send` tri-state: NOT_DELIVERED, DELIVERED_NO_ECHO or ACKED.
   - Advance the sequence only when the frame was delivered.
   - A lost echo still advances it, because repeating a sequence number also latches.
3. **`soak.py:72-111`: the gate can pass a run with no data (the L12 failure mode).**
   With 0 samples, 0 policy steps or an empty tick log, p99.9 = 0 and the hb-gap count = 0, so `check_soak_report(strict=True)` returns `(True, [])`.
   **Fix:**
   - Fail when samples < 0.9 · minutes · 60 · servo_hz.
   - Fail when policy steps are below the expected count.
   - Fail when minutes is under a floor.
   - Add a test with an empty log.
4. **Safety rules with no test.** Each mutation below left all 150 servo tests green:
   - `core.py:382`: forcing the pre-reenergize heartbeat to `= True`.
   - `:474`: deleting `pipe.resync`.
   - `:713`: deleting the shutdown heartbeat. The test ramp is shorter than the MCU's 1 s timeout.
   - `:541`: changing the thermal-resume gate to `if True`.
   - `:494`, `:502`, `:513`, `:591`: dropping, respectively, the core `check_range`, the HOLD `ok` guard, `torque_ok`, or the `safe_started` reset.

   **Fix:** add FakeMcu or heartbeat-sink tests that fail on each of these mutations.
   - Use a shutdown ramp longer than 1 s.
   - Add a thermal resume where the heartbeat is refused.

## SHOULD-FIX

5. **`core.py:518-519`: one refused heartbeat latches.** This is spec-conformant but brittle.
   **Decided:** latch on MCU `status().latched`, or after 5 consecutive missed acknowledgements (about 150 ms).
   - Reenergize stays strict.
   - Update ARCHITECTURE §5/§6 and `state_machine.py:166` to match.
6. **`process.py:165`: only SIGINT and SIGTERM are handled.**
   When an ssh session closes, SIGHUP kills the process with no ramp, so the arm falls about 1 s later.
   **Fix:** add SIGHUP and SIGQUIT, with a test.
7. **`core.py:390` / `reenergize.py`: reenergize never checks for an abort.**
   Ctrl-C and STOP_REQ are ignored for up to about 5 s, and a thermal resume can start after a stop signal.
   **Fix:** add an optional `should_abort` to `reenergize`, and skip the thermal resume once stop is set.
8. **`core.py:549-566`: command handling.**
   - (a) A delta that arrives on a tick where `use_policy` is false is consumed and lost.
   - (b) A command written while waiting for ARM looks fresh on the first RUN tick.
   - (c) A HOLD or IDLE command with a new seq moves HOLD to RUN and triggers a resync.

   **Fix:**
   - In `_reset_command_counters`, drain the command block and sync `_last_cmd_seq`.
   - Treat a command as fresh for the state machine only when its mode is RUN.
   - Keep an unapplied delta pending instead of dropping it.
9. **`core.py:622-636`: a failed read publishes the previous `present` with a fresh timestamp and no flag.**
   **Decided:** add a `read_ok` field to the F3 state record. Update `shm.py`, the dtypes, the plan's F3 and ARCHITECTURE §5 to match.
10. **`core.py:631`: HOLD, SAFE and TORQUE_OFF records keep the last RUN `applied_delta`.**
    **Fix:** zero the applied delta whenever apply does not run.
11. **`core.py:359` / `main.py:85`: the ARM wait has no timeout by default.**
    **Fix:** add a default timeout or a periodic reminder log.
12. **`soak.py:105`: the hb-gap check ignores silence before the first heartbeat and after the last, and doesn't count HOLD.**
    **Fix:** use the window's start and end as gap endpoints.
13. **`fake_bus.py:244` vs `feetech_bus.py:132-137`: the fake's "write accepted" semantics differ from the real bus.**
    On hardware, a sync write returning True only means it was transmitted.
    **Fix:** document this, and make the fake's faults match.
14. **`shm.py:294`: the single-instance lock is keyed on the shm name, so two servos could share one serial port.**
    **Fix:** also flock on the serial-port path.
15. **`pyproject.toml:106`: the README's fake soak command fails on a clean host,** because it falls back to the HF-cache calibration.
    **Fix:** pass `--calibration tests/data/...`, or add a `soak-fake` task.
16. **`latency.py:47`: failed reads are counted in the latency stats,** and the hardware test (`test_latency.py:78`) doesn't check that torque is off before writing `Goal_Position`.
    **Fix:** exclude failed reads, and assert that torque is off.
